# 发布指南

## 当前项目状态

项目名称：哔哩哔哩网站动态页：精准时间显示与视频书签跳转。

仓库：[bilibili-dynamic-bookmarks（动态书签项目）](https://github.com/SiH-zh/bilibili-dynamic-bookmarks)。

当前版本：`1.2.0`，公开发布并配置自动更新。代码、说明、测试、许可证和工作流均在项目根目录内。所有原始提交与历史标签均保留；每个版本在发布页提供对应脚本，不改写旧标签。

## 上传到代码托管平台

本地仓库已关联远程地址。发布前检查目标地址和工作区，随后推送主分支与全部标签；不使用强制推送。

```sh
git remote -v
git status --short
git push -u origin main
git push origin --tags
```

也可以在网页上传源代码压缩包解压后的项目文件。网页上传不会保留本地提交历史；希望保留历史时使用本地仓库推送，或先从附带的仓库备份文件恢复。

请只上传项目文件，开发依赖目录、个人标记、浏览器信息、调试数据和本机路径不应进入仓库。当前忽略规则已排除依赖目录、测试截图、日志和压缩包。

## 创建版本发布

在[版本发布页](https://github.com/SiH-zh/bilibili-dynamic-bookmarks/releases)选择对应标签，填写中文标题和更新说明，上传该标签下的`.user.js`（油猴脚本文件）及校验值。安装用户不需要开发依赖；源代码可以从标签自动生成的压缩包取得。

本项目包含只读权限的自动检查工作流：推送和提交合并请求时运行语法、版本与功能测试。工作流不自动创建正式发布，也不自动上传用户数据。

自动更新地址与下载地址均为主分支的原始脚本：`https://raw.githubusercontent.com/SiH-zh/bilibili-dynamic-bookmarks/main/bilibili-dynamic-bookmarks.user.js`。发布新版本需要同时更新主分支和版本号，仅创建标签不会改变主分支的更新内容。1.1.1之后保持脚本名称、命名空间与存储键稳定。

## 后续版本

1. 兼容性修复或缺陷修复递增修订号，例如 `1.2.1`；新增功能递增次版本号，例如 `1.3.0`；不兼容的功能或存储变化递增主版本号。
2. 同步修改脚本头的 `@version`、脚本内部 `VERSION`、`package.json`（项目配置）和依赖锁文件中的项目版本。
3. 更新主说明与更新记录。运行 `npm install --package-lock-only --ignore-scripts` 更新锁文件。
4. 运行 `npm run check` 与 `npm test`，并完成实际浏览器验收。
5. 提交修改后创建新版本标签。已经发布的标签不要挪动；有问题时发布修订版本。

```sh
git add .
git commit -m "修复：说明具体变化"
git tag -a v1.2.1 -m "发布 1.2.1"
git push origin main
git push origin v1.2.1
```

## 本地仓库备份

随交付提供的 `.bundle` 文件是包含主分支、提交历史和版本标签的本地仓库备份。可在新目录恢复：

```sh
git clone bilibili-dynamic-bookmarks-v1.2.0.bundle bilibili-dynamic-bookmarks
```

源代码压缩包适合查看和网页上传；仓库备份适合保留版本历史。
