# 发布指南

## 当前项目状态

项目名称：哔哩哔哩动态精确时间与视频标记。

建议仓库名称：`bilibili-dynamic-bookmarks`。

当前版本：`1.0.0`，为首个正式版。代码、说明、测试、许可证和工作流均在项目根目录内。没有预设远程仓库地址，也没有自动上传或公开发布。本地保留 `v0.1.0`、`v0.1.1` 与 `v1.0.0` 标签。

## 上传到代码托管平台

可以将当前本地仓库关联到自己新建的空仓库，再推送主分支与版本标签。命令中的地址需要替换成实际仓库地址，不要保留占位符。

```sh
git remote add origin 实际仓库地址
git push -u origin main
git push origin --tags
```

也可以在网页上传源代码压缩包解压后的项目文件。网页上传不会保留本地提交历史；希望保留历史时使用本地仓库推送，或先从附带的仓库备份文件恢复。

请只上传项目文件，开发依赖目录、个人标记、浏览器信息、调试数据和本机路径不应进入仓库。当前忽略规则已排除依赖目录、测试截图、日志和压缩包。

## 创建版本发布

在仓库的版本发布页面选择 `v1.0.0` 标签，填写“1.0.0 正式版：精确时间与视频标记”，说明当前验证范围，并上传根目录的 `.user.js` 脚本。安装用户只需要该文件，不需要开发依赖。

本项目包含只读权限的自动检查工作流：推送和提交合并请求时运行语法、版本与功能测试。工作流不自动创建正式发布，也不自动上传用户数据。

仓库地址确定后，可以为脚本增加真实的项目主页、问题反馈、下载和自动更新地址。在此之前不填写虚构地址。添加自动更新地址时保持 `@namespace` 与脚本名称稳定，并确认地址指向对应分支的原始脚本内容。

## 后续版本

1. 兼容性修复或缺陷修复递增修订号，例如 `1.0.1`；新增功能递增次版本号，例如 `1.1.0`；不兼容的功能或存储变化递增主版本号。
2. 同步修改脚本头的 `@version`、脚本内部 `VERSION`、`package.json`（项目配置）和依赖锁文件中的项目版本。
3. 更新主说明与更新记录。运行 `npm install --package-lock-only --ignore-scripts` 更新锁文件。
4. 运行 `npm run check` 与 `npm test`，并完成实际浏览器验收。
5. 提交修改后创建新版本标签。已经发布的标签不要挪动；有问题时发布修订版本。

```sh
git add .
git commit -m "修复：说明具体变化"
git tag -a v1.0.1 -m "发布 1.0.1"
git push origin main
git push origin v1.0.1
```

## 本地仓库备份

随交付提供的 `.bundle` 文件是包含主分支、提交历史和版本标签的本地仓库备份。可在新目录恢复：

```sh
git clone bilibili-dynamic-bookmarks-v1.0.0.bundle bilibili-dynamic-bookmarks
```

源代码压缩包适合查看和网页上传；仓库备份适合保留版本历史。
